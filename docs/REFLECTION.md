# Short Reflection Report (200–300 words)

The main challenge in comparing React, Angular, Vue, and Svelte was keeping the workload consistent while each framework uses a different rendering model and development setup. I used the same to-do list requirements, task counts, priorities, and operations in each application. The benchmark measures rendering 100, 500, and 1,000 tasks, followed by an update and deletion of 50 tasks. Keeping the browser, machine, and build mode consistent is important because browser scheduling and development tooling can affect the timings.

React updates the interface through component rendering and state changes, while Angular uses its template and change-detection system. Vue tracks reactive state and updates affected template output, and Svelte compiles component code to perform targeted updates. These differences can influence the amount of work done during each operation, but framework design alone does not establish which implementation is fastest. Task keys, application code, runtime mode, browser version, and measurement noise also matter.

I will compare the median of at least five runs for every workload rather than relying on a single result. **The fastest framework for each scenario must be identified from the measured table in `RESULTS_TEMPLATE.md`; I have not assigned a winner before collecting data.** If one framework performs better in this test, that conclusion applies to this specific list workload and environment, not all applications. The exercise showed me that meaningful performance comparisons require controlled conditions, repeatable operations, transparent measurement, and careful interpretation rather than assumptions based on a framework's reputation.
